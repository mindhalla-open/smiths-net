# Offline ASR Voice Assistant (`asr_bot.py`)

A fully **offline**, low-latency voice assistant for inbound phone calls,
built on `smiths-net`. It answers a SIP trunk call, listens, transcribes,
asks a local LLM for a reply, speaks it back, and can end the call on its
own — all on a single GPU, with **no cloud services**.

The reference deployment is a **Megafon Multifon** SIP trunk, but the bot
also runs in a local loopback mode for development.

---

## Pipeline at a glance

```
   PSTN / SIP trunk (Megafon)
            │  SIP/RTP (G.711 A-law/µ-law, 8 kHz)
            ▼
     ┌──────────────┐        MCP stdio (JSON-RPC)      ┌─────────────────────────┐
     │  smiths-net  │ ───────────────────────────────▶ │ AI sidecar plugins (GPU)│
     │  engine      │   transcribe / llm_chat /        │                         │
     │ (SIP+RTP+    │   synthesize                     │  ai-asr-faster-whisper  │ STT
     │  rendezvous) │ ◀─────────────────────────────── │  ai-llm-llamacpp        │ LLM
     └──────────────┘                                  │  ai-tts-silero          │ TTS
            ▲                                           └─────────────────────────┘
            │  asr_bot.py drives the dialogue loop
            │  (VAD → STT → LLM → TTS → RTP)
       conversation
```

The engine handles signaling and media; `asr_bot.py` is the dialogue
brain and calls the AI plugins over MCP.

### The offline AI stack

| Stage | Plugin | Model | Notes |
|-------|--------|-------|-------|
| **STT** | `ai-asr-faster-whisper` | Whisper `large-v3` (CTranslate2) | `int8_float16` on GPU; built-in VAD + hallucination filter |
| **LLM** | `ai-llm-llamacpp` | Gemma-2-9B-it `Q4_K_M` | llama.cpp server, all layers on GPU (`-ngl 99`) |
| **TTS** | `ai-tts-silero` | Silero `v5_5_ru` (xenia) | 24 kHz synth → anti-aliased downsample to 8 kHz |

All three fit together on a 12 GB GPU (e.g. RTX 4070 Ti). Each leg can be
swapped via `ASR_PLUGIN` / `LLM_PLUGIN` / `TTS_PLUGIN` (e.g. `ai-tts-piper`
for a PyTorch-free TTS).

## Quick start

```bash
# 1. Install venv + all models + llama.cpp + Gemma (turnkey, ~10 GB download)
bash examples/setup-offline.sh

# 2. Smoke-test each component
bash examples/test-offline.sh

# 3a. Local loopback (no trunk): park the bot, call it from another shell
bash examples/restart-asr-bot.sh        # uses examples/offline.env
#    in a second terminal:
python3 examples/python-client/voice_caller.py --out tmp/asr-bot-reply.wav

# 3b. Megafon trunk: fill in credentials, then start LLM + bot together
cp examples/multifon.env.example examples/multifon.env   # edit creds
bash examples/start-offline-stack.sh    # llama-server (bg) + bot (fg)
```

### `bot.toml` — persona, prompt, and gender

The system prompt and the assistant's grammatical gender live here, so you
can re-voice the bot without touching code:

```toml
[bot]
gender = "female"   # female | male | neutral
greeting = "Здравствуйте! Чем могу помочь?"

[prompt]
base = """<general dialogue rules, gender-agnostic>…"""

[gender.female]
instruction = """<feminine self-reference only>…"""
```

`gender` selects the `[gender.*]` block **and** toggles deterministic
feminine post-processing of LLM replies. Override anything with env vars:
`BOT_SYSTEM_PROMPT`, `BOT_GREETING`, `BOT_FEMINIZE`, `BOT_CONFIG`.

## Conversation features

- **Energy VAD with speculative turn-taking.** While the caller pauses, the
  bot starts drafting the reply (STT→LLM→TTS) at
  `VAD_SPECULATE_SILENCE_SECS`; if the caller resumes, the draft is thrown
  away. If the pause becomes a real end-of-turn, the answer is already
  rendered and plays instantly — the natural commit window
  (`VAD_SILENCE_SECS`) costs ~no extra latency.
- **Barge-in.** The caller can talk over the bot; playback stops and the bot
  listens (`BARGE_IN`, `BARGE_THRESHOLD`).
- **Pre-rendered greeting** with a short silence lead-in so the first word is
  never clipped while the carrier's RTP pinhole latches.
- **Feminine self-reference** enforced both in the prompt and via a
  post-processor (`понял`→`поняла`, …) when `gender = female`.
- **Single greeting.** A redundant second “Здравствуйте” from the model is
  stripped deterministically.
- **Assistant-initiated hang-up.** When the dialogue is over, the LLM appends
  an `[ОТБОЙ]` marker; the bot strips it, says the farewell, and drops the
  call via SIP BYE. The engine propagates the BYE to the trunk leg so the
  call actually terminates (see engine changes below).

## Modes

- **`--mode local`** — the bot parks on the `voicebot` rendezvous key; call it
  with `voice_caller.py`. Good for development without a trunk.
- **`--mode trunk`** — outbound `REGISTER` to the carrier, waits for inbound
  `INVITE`s on the DID, bridges in as the second leg, and converses.
- **`--mode auto`** — `trunk` if `SIP_REGISTRAR` is set, else `local`.

---

## Megafon trunk / NAT notes

Inbound calls over a home/NAT connection need:

- `SIP_PUBLIC_ADDRESS` / `advertise_ip` set to the **port-forwarded public
  IP** the carrier reaches (not a CGNAT egress). Auto-IP detection is
  **opt-in** (`ENABLE_IP_SYNC=1`) precisely because the detected address is
  often wrong behind CGNAT.
- A **persistent REGISTER socket** refreshed every ~25 s to keep the NAT UDP
  binding open (handled by `sip_register.py`).
- **RTP keepalive** during listening + a longer `RTP_PRIME_SECS` so symmetric
  RTP trunks latch the relay before the greeting.
- Port-forwarding for SIP (5060/udp) and the RTP range. See
  `examples/open-megafon-ports.sh` and
  `examples/python-client/README-megafon-tplink.md`.

## Tuning knobs (`offline.env`)

| Variable | Default | Effect |
|----------|---------|--------|
| `VAD_SILENCE_SECS` | `0.8` | trailing silence that ends a turn |
| `VAD_SPECULATE_SILENCE_SECS` | `0.35` | pause before drafting a speculative reply |
| `VAD_THRESHOLD` | `250` | RTP energy speech threshold |
| `VAD_SPIKE_TOLERANCE` | `2` | loud frames tolerated before silence resets |
| `RECORD_SECS` | `10.0` | max single-utterance capture |
| `BARGE_IN` / `BARGE_THRESHOLD` | `1` / `900` | interrupt-the-bot sensitivity |
| `RTP_PRIME_SECS` | `0.4` | silence burst that latches the RTP relay |
| `GREETING_LEAD_SILENCE_SECS` | `0.3` | silence pad before the greeting |
| `BOT_MAX_TURNS` | `200` | hard cap on dialogue turns |
| `BOT_IDLE_TURNS_MAX` | `3` | consecutive silent turns before giving up |
| `LLM_MAX_TOKENS` | `160` | reply length cap (latency vs completeness) |
| `LLM_HISTORY_MSGS` | `6` | dialogue turns kept in context (prompt-cache prefix) |
| `FW_COMPUTE_TYPE` | `int8_float16` | whisper VRAM/accuracy trade-off |

## Requirements

- NVIDIA GPU with ~12 GB VRAM (CPU fallback works but is slow:
  set `FW_DEVICE=cpu` / `SILERO_DEVICE=cpu`).
- Python 3.10+ with a venv (created by `setup-offline.sh`).
- `wget`, `curl`, `tar` for model/binary downloads.
- A built engine: `CARGO_TARGET_DIR=target cargo build --release -p smiths-cli`.
