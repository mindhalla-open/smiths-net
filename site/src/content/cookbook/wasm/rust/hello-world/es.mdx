## Descripción general

Esta receta te guía paso a paso para construir el plugin WASM más
sencillo posible para Smiths-Net: un crate Rust con `#![no_std]` que
compila a `wasm32-unknown-unknown` y llama a la función host
`smiths::log` del motor al iniciarse.

Al finalizar tendrás:

1. Un crate Rust independiente que compila a un módulo `.wasm`.
2. Un manifiesto `plugin.toml` que el motor lee al arrancar.
3. Un plugin funcional que imprime un saludo en el log del motor.

## Requisitos previos

- Toolchain de Rust (vía `rustup`) con el target `wasm32-unknown-unknown`:

  ```bash
  rustup target add wasm32-unknown-unknown
  ```

- Una instancia de `smiths-net` en ejecución — la forma más rápida:

  ```bash
  smiths-net init --preset dev --non-interactive
  smiths-net --config config.toml
  ```

## 1. Crear el crate

```bash
mkdir -p hello-world/src
cd hello-world
```

Crea `Cargo.toml`:

```toml
# Cargo.toml
[package]
name         = "hello-world"
version      = "0.1.0"
edition      = "2024"
rust-version = "1.95"
publish      = false
description  = "Minimal WASM plugin — calls smiths::log."

# Raíz de workspace independiente para compilar este crate de forma aislada.
[workspace]

[lib]
crate-type = ["cdylib"]

[profile.release]
lto           = true
codegen-units = 1
opt-level     = "s"
strip         = "symbols"
```

Puntos clave:

- **`crate-type = ["cdylib"]`** — produce un `.wasm` de biblioteca
  compartida que solo exporta los símbolos marcados con
  `#[unsafe(no_mangle)]`.
- **`[workspace]`** — un bloque workspace vacío hace que este crate sea
  independiente del workspace padre de smiths-net.
- **Perfil release** — `lto = true` + `opt-level = "s"` mantiene el
  archivo de salida por debajo de 1 KiB.

## 2. Escribir el plugin

```rust
// src/lib.rs
#![no_std]
#![no_main]

// Importar la función log del host. El atributo `wasm_import_module`
// le dice al linker que busque este símbolo bajo el módulo `smiths`
// — el motor lo proporciona automáticamente.
#[link(wasm_import_module = "smiths")]
unsafe extern "C" {
    fn log(ptr: *const u8, len: usize);
}

/// Wrapper delgado para mantener las llamadas seguras.
fn host_log(msg: &str) {
    unsafe {
        log(msg.as_ptr(), msg.len());
    }
}

const GREETING: &str = "hello-world: hook fired";

/// Punto de entrada que el motor invoca vía `WasmEngine::run_entry`.
#[unsafe(no_mangle)]
pub extern "C" fn run() {
    host_log(GREETING);
}

/// Los panics no deben propagarse al código host — abortar con trap.
#[panic_handler]
fn panic(_info: &core::panic::PanicInfo) -> ! {
    core::arch::wasm32::unreachable()
}
```

Recorrido del código:

| Elemento | Propósito |
|----------|-----------|
| `#![no_std]` | Sin biblioteca estándar — los guests WASM no tienen OS. |
| `#![no_main]` | Sin `main()` — el motor llama a `run()` directamente. |
| `#[link(wasm_import_module = "smiths")]` | Enlaza el extern `log` con la importación host `smiths.log`. |
| `#[unsafe(no_mangle)]` | Preserva el nombre del símbolo para que el motor lo encuentre. |
| `extern "C" fn run()` | Exportación C ABI que el motor invoca al cargar el plugin. |
| `#[panic_handler]` | Requerido en targets `no_std` — trap en lugar de unwinding. |

## 3. Compilar

```bash
cargo build --target wasm32-unknown-unknown --release
```

La salida se encuentra en:

```
target/wasm32-unknown-unknown/release/hello_world.wasm
```

Verifica el tamaño — debería ser minúsculo (< 1 KiB):

```bash
ls -lh target/wasm32-unknown-unknown/release/hello_world.wasm
```

## 4. Crear el manifiesto del plugin

Cada plugin necesita un `plugin.toml` que le indica al motor qué está
cargando:

```toml
# plugin.toml
name        = "hello-world"
version     = "0.1.0"
type        = "wasm"
entry       = "./hello_world.wasm"
provides    = []
permissions = []
abi         = "1.0"
description = "Minimal hello-world WASM plugin."
```

| Campo | Significado |
|-------|-------------|
| `type` | `"wasm"` le dice al motor que use el cargador WASM. |
| `entry` | Ruta relativa desde `plugin.toml` al binario `.wasm`. |
| `provides` | Capacidades que el plugin ofrece (vacío por ahora). |
| `permissions` | Recursos del host a los que puede acceder (vacío = solo log). |
| `abi` | Versión del ABI — debe coincidir con la versión esperada por el motor. |

## 5. Cargar en el motor

Copia los archivos al directorio de plugins del motor y reinicia
(o recarga en caliente):

```bash
mkdir -p plugins/hello-world
cp target/wasm32-unknown-unknown/release/hello_world.wasm plugins/hello-world/
cp plugin.toml plugins/hello-world/
```

Luego reinicia:

```bash
smiths-net --config config.toml
```

O recarga en caliente el motor en ejecución:

```bash
smiths-net reload --pid $(pgrep smiths-net)
```

Deberías ver en los logs del motor:

```
INFO smiths_wasm: plugin loaded name="hello-world"
INFO smiths_wasm: hello-world: hook fired
```

## Lo que omitimos

Este plugin hello-world solo exporta `run()`. Un plugin de producción
también exporta:

- **`describe()`** — retorna un descriptor JSON de capacidades para que
  el motor sepa qué herramientas proporciona el plugin.
- **`alloc(len)`** — un allocador bump que el motor usa para escribir
  datos en la memoria del guest.
- **`invoke(method_ptr, method_len, params_ptr, params_len)`** —
  el dispatcher de herramientas que el motor llama cuando un cliente
  MCP/A2A invoca una herramienta del plugin.
